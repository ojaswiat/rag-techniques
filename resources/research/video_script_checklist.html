    Nuance 2 · why retrieval needs no model

    This is the point markers most often miss, so it is worth being blunt about on camera. The pipelines never write anything. Both halves below are real rows from benchmark.db.

    one row from nodes
    node_id            = MSFT_2023_n0387
document_id        = MSFT_2023
parent_item_header = Item 1B. Unresolved
                     Staff Comments
node_type          = text
content            = "We have received no
  written comments regarding our periodic
  or current reports from the staff of the
  Securities and Exchange Commission..."
    the matching row in queries
    query_id     = QT1_PQ_003
quadrant     = Q1_Direct_Text
query_text   = "What does the company state
  regarding written comments from the SEC
  staff issued 180 days or more before the
  end of fiscal year 2023..."
gt_citations = ["MSFT_2023_n0387"]

    So the whole scoring step is one question: did the pipeline return n0387? That is a set comparison, which is arithmetic. Nothing has to think, so no model is needed, so the numbers come out identical on every run.

    The one exception, if pressed: P3's tree was written by a model back in Phase 3, at a cost of 1.73M tokens. That result sits frozen on disk. A MockLLM is bound when it loads, so a live call at query time is impossible rather than merely unlikely.
